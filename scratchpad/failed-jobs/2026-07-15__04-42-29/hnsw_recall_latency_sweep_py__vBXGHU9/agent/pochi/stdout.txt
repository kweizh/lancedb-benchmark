## What the solution does

### `build_index()`
- Connects to the LanceDB database at `$LANCEDB_URI` and opens the table `vectors_$ZEALT_RUN_ID`.
- Calls `tbl.create_index()` with `index_type="IVF_PQ"`, `metric="l2"`, `num_partitions=64`, `num_sub_vectors=8`, and `replace=True` (so it is safe to call multiple times).
- Blocks via `tbl.wait_for_index(["vector_idx"], ...)` until the index is fully persisted before returning.

### `sweep(query_set, param_grid, k=10)`
1. **Ground-truth computation** — for every query vector, performs a `bypass_vector_index()` exhaustive scan to get the exact top-k IDs. Ties are broken deterministically by `(_distance ASC, id ASC)`.
2. **Cartesian product sweep** — iterates every `(nprobes, refine_factor)` pair (sorted ascending), runs ANN search for each query using `.nprobes(n).refine_factor(r).limit(k)`, and measures wall-clock latency with `time.perf_counter()`.
3. **Recall@k** — computed as `|ANN_ids ∩ exact_ids| / k` per query, then averaged over all queries.
4. Returns a `list[dict]` sorted by `(nprobes, refine_factor)` with exactly the keys: `nprobes`, `refine_factor`, `recall`, `mean_latency_ms`.
