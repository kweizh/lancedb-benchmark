import hashlib, math, numpy as np

def compute_vector(title, body):
    text = (title or '') + ' ' + (body or '')
    vec = np.zeros(32, dtype=np.float64)
    for token in text.lower().split():
        digest = hashlib.md5(token.encode('utf-8')).hexdigest()
        bucket = int(digest, 16) % 32
        vec[bucket] += 1.0
    norm = math.sqrt(float(np.dot(vec, vec)))
    if norm > 0.0:
        vec = vec / norm
    return vec.astype(np.float32)

## What was implemented

### `run_sync.py` — key design decisions

| Concern | Implementation |
|---|---|
| **Binlog reader** | `BinLogStreamReader` with `blocking=False`, `server_id=100` (≠ MySQL server id 1), filtered to `appdb.documents` only |
| **Start coordinate** | If `checkpoint.json` exists → resume from saved `(log_file, log_pos)`; otherwise → `SHOW BINARY LOGS` → earliest file at position 4 |
| **INSERT / UPDATE** | Batched into a single `merge_insert("id").when_matched_update_all().when_not_matched_insert_all().execute(arrow_batch)` |
| **DELETE** | `table.delete(f"id IN ({ids})")` |
| **Vector embedding** | Deterministic 32-dim bag-of-words: MD5-hashed tokens mod 32 → bucket counts → L2-normalized → stored as `float32` |
| **Arrow schema** | `id int64, title utf8, body utf8, category utf8, price float64, vector fixed_size_list<float32, 32>` |
| **Checkpoint** | Written atomically (`os.replace`) after the stream is drained; saved at the position of the last consumed event |
| **Output** | Exactly one JSON line: `{"inserts": N, "updates": N, "deletes": N, "log_file": "...", "log_pos": N}` |

### Verified behaviours

1. **Cold start (no checkpoint)** — reads all binlog history from the earliest file, replays all INSERTs, UPDATEs, and DELETEs; LanceDB converges to the exact MySQL state.
2. **Idempotent re-run** — resumes from checkpoint, processes zero events, emits `inserts:0, updates:0, deletes:0`.
3. **Incremental sync** — after applying an UPDATE, a DELETE, and an INSERT directly to MySQL, the next run captured `inserts:1, updates:1, deletes:1` and the LanceDB table converged exactly.
4. **Vector correctness** — L2 norm of every stored vector is 1.0 and independently recomputed vectors match stored ones bit-for-bit.
5. **Schema correctness** — all five non-vector columns match MySQL types/values; `vector` is always 32-dimensional float32.
