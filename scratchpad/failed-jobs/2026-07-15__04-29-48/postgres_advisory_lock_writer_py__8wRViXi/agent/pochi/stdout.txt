## How it works

**Locking (PostgreSQL advisory locks):** Each call opens a fresh `psycopg2` connection (using the `PG*` env vars via libpq defaults) and acquires a session-level advisory lock using the integer key from `PG_LOCK_KEY`:
- `guarded_write` → `SELECT pg_advisory_lock(%s)` (blocks until held).
- `try_write` → `SELECT pg_try_advisory_lock(%s)`; if it returns false, the function returns `None` immediately without writing or consuming a sequence number.

The lock is released with `pg_advisory_unlock` in a `finally` block (tracked via an `acquired` flag so we only unlock what we hold), and the connection is closed afterwards as a backstop — so the lock is **always** released even if the critical section raises.

**Critical section (`_do_write`, shared by both):**
1. Opens the LanceDB tables `records_<ZEALT_RUN_ID>` and `audit_<ZEALT_RUN_ID>` from `LANCEDB_URI`.
2. Computes the next sequence as `max(seq) + 1` from the audit table (1 when empty). Holding the advisory lock makes this read-modify-write safe.
3. Stamps every row with `writer_id` and the assigned `seq`, then upserts into the data table keyed on `id` via `merge_insert("id").when_matched_update_all().when_not_matched_insert_all()`.
4. Appends exactly one audit record with keys `seq`, `writer_id`, `value` (the shared value of the operation's rows), and `ids_json` (JSON array of written ids).
5. Returns the assigned sequence number.

**Robustness detail:** Data rows are built as an explicit pyarrow Table with `vector` as a fixed-size `list<float32>[8]` (via `FixedSizeListArray.from_arrays`), guaranteeing the column exactly matches the target schema and avoiding any dict-inference/casting issues.
