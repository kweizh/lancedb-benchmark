## How it works

**Keyword ranking (`_keyword_ranking`)** — Connects to MariaDB via PyMySQL using the `MARIADB_*` env vars, builds the table name `docs_{ZEALT_RUN_ID}`, and runs:
```sql
SELECT id FROM `docs_<run_id>`
WHERE MATCH(body) AGAINST (%s IN NATURAL LANGUAGE MODE)
ORDER BY MATCH(body) AGAINST (%s IN NATURAL LANGUAGE MODE) DESC, id ASC
```
The returned id order is the keyword ranking (rank 1 = best). Ties are broken by `id ASC` for determinism. No `LIMIT`, so every positive-relevance doc is included.

**Vector ranking (`_vector_ranking`)** — Opens the LanceDB table at `LANCEDB_PATH`, runs a cosine-distance search over the `vector` column fetching all rows (`limit(count_rows())`), then re-sorts by `(_distance ASC, id ASC)` so the order is fully deterministic regardless of LanceDB's internal tie handling.

**RRF fusion (`_rrf_fuse`)** — For each list, a document at 1-based position `rank` contributes `1 / (60 + rank)`. Scores are summed across both lists. Results are sorted by `score` descending, ties broken by `id` ascending, and truncated to `k`.

## Key correctness properties
- **Constant = 60** exactly as specified.
- **Both-list docs float to the top**: a doc at rank 1 in both lists scores `2/61 ≈ 0.0328`, beating any single-list doc (max `1/61 ≈ 0.0164`).
- **Single-list matches are still included** (a doc missing from one list simply contributes nothing for that list).
- **Deterministic**: per-list tie-breaking (`id ASC`) plus the final sort key `(-score, id)` guarantee identical output for identical inputs.
- **Return shape**: list of `{"id": int, "score": float}`, at most `k` items.

The pure RRF fusion logic was unit-tested against hand-computed scores (including tie-breaking, `k` truncation, empty-list, and both-list-vs-single-list cases) — all assertions passed. The LanceDB result schema was verified: results are dicts containing the stored `id` column plus `_distance` (ascending = most similar), which the code uses for ordering.
