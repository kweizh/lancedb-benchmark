# MySQL Binlog CDC Indexer into LanceDB

## Background
You are building a Change-Data-Capture (CDC) pipeline that keeps a LanceDB search index continuously converged with a MySQL source table. A MySQL 8 server is already running locally inside this environment with **row-based binary logging** enabled (`binlog_format=ROW`, `binlog_row_image=FULL`, `binlog_row_metadata=FULL`). Your indexer must read MySQL binlog row events (INSERT / UPDATE / DELETE) and replicate every change into a LanceDB table, so that the LanceDB table always reflects the exact current contents of the MySQL source table.

The indexer must be **restartable**: it has to persist the binlog coordinate (file name + position) it has consumed so far, and on the next run it must resume from that checkpoint and process only the new events — it must never re-apply events it already consumed and must never miss events.

## Requirements
- Read MySQL binlog row events for the source table `appdb.documents` and replicate them into a LanceDB table.
- Handle all three row-event types: INSERT and UPDATE become primary-key upserts into LanceDB; DELETE removes the row from LanceDB.
- Persist the last consumed binlog coordinate (log file + log position) to a checkpoint file. On start, resume from the checkpoint if present; if no checkpoint exists, replicate from the beginning of the available binlog so that a freshly-initialized (empty) source table is captured in full.
- The command must be non-blocking: it drains all currently-available binlog events, applies them, updates the checkpoint, prints a summary, and exits.
- After running, the LanceDB table must be fully converged with the MySQL source table (same set of primary keys, same column values, and a vector for every row).

## Implementation Hints
- The MySQL replication protocol is easiest to consume from Python with the `mysql-replication` package (`from pymysqlreplication import BinLogStreamReader`, with `WriteRowsEvent` / `UpdateRowsEvent` / `DeleteRowsEvent` from `pymysqlreplication.row_event`). Read from the stream in a non-blocking way and stop once the current end of the binlog is reached. The reader must connect with a `server_id` that is different from the MySQL server's own id (the server uses id `1`).
- Track the coordinate after each processed event; the stream object exposes the current `log_file` and `log_pos`. To resume, reopen the stream with `resume_stream=True` and the saved `log_file`/`log_pos`. To start from the beginning of the earliest binlog, use the first file reported by `SHOW BINARY LOGS` at position `4`.
- Use LanceDB's primary-key merge/upsert (`merge_insert("id") ... execute(...)`) for INSERT/UPDATE and `table.delete(...)` for DELETE. Create the LanceDB table if it does not yet exist.
- Project path: `/home/user/myproject`
- MySQL connection parameters are provided via environment variables: `MYSQL_HOST` (127.0.0.1), `MYSQL_PORT` (3306), `MYSQL_USER`, `MYSQL_PASSWORD`. The source database is `appdb` and the source table is `documents`.

- Persist the LanceDB database under the directory `/home/user/myproject/lancedb` and name the table `documents_index`. Persist the binlog checkpoint to the file `/home/user/myproject/checkpoint.json`.
